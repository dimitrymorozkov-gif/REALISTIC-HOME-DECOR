# Проверка Realistic Home Decor

Этот документ — воспроизводимый протокол. Наличие команды или пункта в таблице не означает, что проверка выполнена. Фактические результаты сборки и запуска приведены в README; результаты измерений FPS записываются отдельно по [PERFORMANCE.md](PERFORMANCE.md).

## Автоматические проверки

Из корня проекта, с Java 21 и Python 3.10 или новее:

```bash
./gradlew --no-daemon build
python3 -m unittest discover -s tests -v
python3 tools/scene_generator.py
python3 tools/scene_generator.py --check
```

`build` генерирует ресурсы и выполняет `validateResources`. Валидатор проверяет JSON, ссылки на модели/текстуры, blockstates, файлы предметов, идентификаторы, локализацию, геометрию и каталог. Эти проверки обнаруживают ошибки данных; они не заменяют запуск Minecraft. `--check` проверяет повторяемость уже созданного datapack относительно текущего каталога.

Генератор сцен использует только стандартную библиотеку Python и по умолчанию записывает файлы в `build/test-datapack`. Он не ищет сохранения Minecraft и не размещает блоки в мире. Полные многоблочные предметы создаются из всех `parts` каталога, вторичные ячейки не считаются отдельными предметами. Каталог с неподдерживаемой схемой, повторяющимися ID или пересечением опоры с мебелью отклоняется.

## Клиент и выделенный сервер

1. Запустить `./gradlew runClient`, создать отдельный творческий тестовый мир. Проверить загрузку без ошибок моделей, текстур и регистрации в `run/client/logs/latest.log`.
2. Проверить английский и русский языки, вкладки каталога, иконки и поиск по названию. Отсутствующие модели/текстуры, пустые названия и неработающие предметы — ошибки.
3. Для проверки выделенного сервера запустить `./gradlew runServer`. При первом запуске прочитать Minecraft EULA и принять её только при согласии. Не менять `eula=false` автоматически. Сервер должен дойти до сообщения `Done`, клиент с тем же модом и Fabric API — подключиться.
4. Повторить размещение/разрушение на сервере. Ошибки загрузки клиентских классов на сервере, разрыв соединения и рассинхронизация блоков недопустимы.

Запуск сервера без подключённого клиента подтверждает загрузку серверной части, но не проверяет рендеринг, интерфейс и действия игрока.

## Проверки действий игрока

Начать с `modern_chair_oak`, `dining_table_oak`, `modern_sofa_oak`, `kitchen_cabinet_oak`, `toilet_oak`, затем пройти все конструкции из [CATALOG.md](CATALOG.md). Проверять реальные предметы из творческого инвентаря, а не только `/setblock`.

| Проверка | Действие | Ожидаемый результат |
|---|---|---|
| Геометрия и текстуры | Осмотреть предмет со всех сторон, сверху и снизу; включить отображение границ блоков F3+G | Раздельные детали модели, корректные материалы, отсутствие фиолетово-чёрных участков и пропавших частей |
| Четыре направления | Поставить предмет, глядя на север, восток, юг и запад | Геометрия, занимаемые ячейки и коллизия поворачиваются согласованно на 90° |
| Коллизия | Подойти к ножкам, спинкам, высоким и широким частям; попробовать пройти между деталями | Коллизия соответствует геометрии, вторичные ячейки не пропускают игрока сквозь мебель |
| Занятые ячейки | Попробовать разместить большую мебель так, чтобы хотя бы одна её ячейка была занята камнем | Размещение отклоняется целиком; чужой блок сохраняется, половина предмета не появляется |
| Граница мира | Попробовать разместить высокий предмет у верхней границы строительства | Нет выхода за границы, зависания или частично установленной мебели |
| Пол, стена, потолок | Поставить настенные и потолочные конструкции на подходящую опору; попробовать неподходящую сторону | Предмет крепится только к допустимой поверхности; опора совпадает с направлением модели |
| Удаление опоры | Удалить несущий блок под мебелью, за настенным предметом или над потолочным | Нет оставшихся вторичных ячеек; поведение выпадения соответствует одной целой вещи |
| Разрушение любой части | В выживании разрушить первичную, затем в отдельном опыте вторичную часть многоблочного предмета | Все его части удаляются; выпадает ровно один предмет, соседняя мебель сохраняется |
| Творческое разрушение | Разрушить многоблочный предмет в творческом режиме | Нет дублирующего выпадения и оставшихся невидимых частей |
| Соединяемые секции | Поставить одинаковые секции/шкафы рядом в одном направлении; убрать среднюю; сравнить разные палитры/направления | Соединяются только совместимые соседи; геометрия и коллизия обновляются после удаления |
| Декоративность | Нажать правой кнопкой на шкаф, кровать, технику и сантехнику | Нет непредусмотренного инвентаря, установки точки возрождения, приготовления еды и других игровых механик |
| Сохранение | Сохранить мир, выйти, перезапустить Minecraft/сервер и вернуться | Все части, направления, соединения и освещение сохраняются; после загрузки нет лишних выпадений |

Для испытаний выпадения очистить инвентарь и место опыта вручную. Не использовать массовый `/kill @e`: это изменяет независимые объекты мира. Сравнивать исходное количество предметов с собранным после каждого отдельного опыта.

## Сцены на 100, 500 и 1000 предметов

Сцены — синтетические галереи с регулярной сеткой для повторяемой нагрузки, а не готовые архитектурные проекты. Они смешивают конструкции и палитры из текущего каталога. В `scene_manifest.json` указаны точные координаты каждой части, количество целых предметов, занятых ячеек, опор и SHA-256 каталога.

**Только отдельный тестовый мир.** Функции `scene_0`, `scene_100`, `scene_500`, `scene_1000` удаляют и заменяют блоки в ограниченном объёме. При стандартном каталоге и начале `(0,81,0)` границы берутся из `build/test-datapack/scene_manifest.json`: прибавить `bounds_relative.min/max` к началу. Генератор печатает каталог, но окончательные размеры следует читать в manifest после повторной генерации. Сохранить резервную копию тестового мира перед запуском. Начало должно оставаться одинаковым для `prepare`, `scene_N`, `verify_N` и `release`.

1. Создать мир `RHD-Benchmark`, сохранить и закрыть. Установить datapack в уже существующий мир:

   ```bash
   test -f run/client/saves/RHD-Benchmark/level.dat && \
     python3 tools/scene_generator.py --output run/client/saves/RHD-Benchmark/datapacks/rhd_test
   ```

   У второй команды нет права менять блоки: она записывает только datapack. Для сервера использовать путь к его отдельному тестовому миру. Папка назначения должна быть пустой либо содержать manifest этого генератора; неизвестные файлы он не перезаписывает.

2. Открыть мир с разрешёнными командами, выполнить `/reload`, проверить `/datapack list enabled`. Формат datapack **94.1** взят из `version.json` официального Minecraft 1.21.11 и его встроенных datapack; используются каталоги `function`, `min_format` и `max_format`.
3. Выполнить подготовку чанков и подождать не менее пяти секунд:

   ```mcfunction
   /execute positioned 0 81 0 run function rhd_test:prepare
   ```

4. Поставить выбранную сцену:

   ```mcfunction
   /execute positioned 0 81 0 run function rhd_test:scene_100
   ```

   Должно появиться зелёное сообщение о завершении. Если его нет, чанки ещё не загружены: подождать и повторить. Обёртка проверяет загрузку всего региона до разрушения блоков. `prepare` временно включает принудительную загрузку чанков, поэтому подходит только отдельный мир.
5. Подождать не менее секунды, затем проверить сохранность всех ожидаемых частей:

   ```mcfunction
   /execute positioned 0 81 0 run function rhd_test:verify_100
   ```

   Ни одного сообщения `MISSING` быть не должно. Проверять после ожидания: целостность многоблочной мебели дополнительно проверяется отложенным тиком. Сообщение «finished» само по себе не означает успех: строки `MISSING` и ошибки в логе считаются отказом. Повторить для `500` и `1000`; `scene_0` оставляет тот же пол без мебели для базового замера.
6. Сохранить и перезапустить мир, затем снова запустить соответствующий `verify_N` с тем же началом. Это проверяет наличие ожидаемых блоков и `facing=north` после загрузки, но не проверяет действия игрока, количество выпадений, коллизии или качество изображения.
7. После измерений снять принудительную загрузку:

   ```mcfunction
   /execute positioned 0 81 0 run function rhd_test:release
   ```

   Блоки сцены остаются. `release` снимает принудительную загрузку во всём тестовом регионе, включая ранее включённую вручную; это ещё одна причина использовать отдельный мир.

Функции ставят все части мебели в одном выполнении до следующего тика и создают пол, задние опоры для настенных предметов и верхние опоры для потолочных. Команды `fill` разбиты на небольшие объёмы, изменение лимитов мира не требуется. Сцены не содержат сущностей, маркеров, постоянно работающей tick-функции и автоматической загрузочной функции. Само включение datapack не перестраивает мир.

Для каждого отказа записать ID предмета, направление, режим игры, одиночный/серверный запуск, шаги воспроизведения, ожидаемое и наблюдаемое поведение, а также относящийся к ошибке фрагмент `latest.log` без секретов и персональных данных.
